# Стандарт: Definition of Done

Завдання готове, коли виконано всі пункти. Колонка «Як» показує, хто
перевіряє: **конвеєр** (падає `npm run check`, хук або CI) чи **рев'ю** (чеклист
у PR).

| # | Пункт | Як |
|---|---|---|
| 1 | Spec інкременту `tasks/NN-*/spec.md` з критеріями прийняття закомічена першою в гілці | конвеєр (формат), рев'ю (порядок) |
| 2 | Кожен критерій має перевірку, і вона зелена | конвеєр |
| 3 | `npm run check` зелений локально (pre-push) і в CI на PR | конвеєр |
| 4 | Рішення, що підпадають під [adr.md](adr.md), оформлені ADR | рев'ю |
| 5 | Аудит `tasks/NN-*/audit.md`: топ-3 розбіжності реалізації зі spec; кожна виправлена зміною spec, стандарту або перевірки, з посиланням на коміт | рев'ю |
| 6 | Артефакти запуску у `tasks/NN-*/reports/` і npm-скрипт, який їх відтворює | рев'ю |
| 7 | `tasks/NN-*/DEFENSE.md` за шаблоном, не більше сторінки | конвеєр (формат) |
| 8 | Якщо працював AI: промпти в `ai/prompts/`, аудит виходу AI в аудиті завдання | рев'ю |
| 9 | Робота йде у feature-гілці, PR змерджено в `main` | рев'ю |
| 10 | У репозиторії немає згенерованих файлів (`node_modules`, кеші, `dist`) | конвеєр (`.gitignore` + рев'ю PR) |

## Чим відрізняється від DoD курсу

DoD курсу каже, *що* здати. Цей додає, *як* це перевірити: пункти 1, 2, 3,
7 не залежать від уважності автора, бо їх ловить конвеєр. Пункт 1 жорсткіший
за курс: критерії мають з'явитися в історії раніше за код, інакше вони
підганяються під реалізацію.
