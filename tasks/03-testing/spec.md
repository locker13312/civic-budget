# Завдання 3. Тестування: unit, інтеграційні, E2E, мутації

Складено AI з моїх відповідей ([ai/prompts/03-testing.md](../../ai/prompts/03-testing.md)), погоджено мною.

## Що і навіщо

Тести вже покривають 97% рядків і 91% гілок, але покриття показує лише,
що код виконувався, а не що тест упав би, якби код був неправильний.
Завдання: розкласти тести на рівні (unit, інтеграційні, E2E), повністю
покрити unit-тестами один модуль і мутаційним тестуванням перевірити, чи
тести справді ловлять помилки в домені й сервісах.

## Рівні тестів

| Рівень | Що підіймає | Де | Команда |
|---|---|---|---|
| Unit | нічого: функції й сервіси з репозиторіями в пам'яті | `test/unit/` | `npm run test:unit` |
| Інтеграційні | застосунок Fastify і справжній PostgreSQL (окрема база на тест) | `test/api/`, `test/db/`, `test/hooks/` | `npm run test:integration` |
| E2E | процес `node src/server.js` на порту, PostgreSQL, HTTP-запити ззовні | `test/e2e/` | `npm run test:e2e` |

E2E проходить один повний шлях: адміністратор створює раунд → мешканці
подають заявки → модератор їх розглядає → мешканці голосують →
адміністратор підбиває підсумки → звіт про реалізацію переможця. Фази
раунду тривають 1–2 секунди, тест чекає справжній час; тестових «гачків»
у коді застосунку немає.

## Мутаційне тестування

Stryker мутує `src/*/domain.js` і `src/*/service.js`; тести для нього —
unit і API-сценарії на статичних даних. Кожен вижилий мутант у звіті має
клас: **прогалина** (тест мав би впасти — тест підсилено), **еквівалентний**
(поведінка не змінилась) або **прийнятний** (зміна не важлива, пояснено чому).

## Критерії прийняття

| ID | Критерій | Перевірка |
|---|---|---|
| AC-3.1 | Модуль `results` (domain, service, репозиторій у пам'яті) має 100% рядків і гілок лише від unit-тестів | `npm run coverage:unit` |
| AC-3.2 | Покриття гілок усього `src` усіма тестами не нижче 80%, інакше збірка падає | `npm run coverage` |
| AC-3.3 | Інтеграційні тести підіймають справжній PostgreSQL і застосунок; кожен тест має свою базу | `npm run test:integration` |
| AC-3.4 | E2E проходить повний шлях від створення раунду до звіту через запущений процес сервера і HTTP | тест |
| AC-3.5 | Mutation score домену й сервісів не нижче 70%, інакше `npm run mutation` падає | `npm run mutation` |
| AC-3.6 | Кожен вижилий мутант зі звіту Stryker має клас і пояснення у звіті мутацій | тест |
